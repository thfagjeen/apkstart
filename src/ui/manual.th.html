  1. (เฉพาะรุ่นน้ำหนักเบา) ดาวน์โหลดรันไทม์: adb, Android Emulator และอิมเมจระบบ Android 14 วัดจริงจากแหล่งทางการได้ 10+ MB/s ใช้ 8 เธรดแบ่งชิ้นและดาวน์โหลดต่อเมื่อขาด รุ่นเต็ม / รุ่น Store ข้ามขั้นตอนนี้
  2. แตกอิมเมจครั้งแรก: อิมเมจ xz ถูกแตกไปที่ %APPDATA%\apkstart\system-images (ประมาณ 20 วินาที ทำครั้งเดียว)
  3. สร้าง /data ครั้งแรก: ApkStart สร้างข้อมูลผู้ใช้แบบ ext4 ที่มีการเข้ารหัสและป้ายกำกับ SELinux ให้เอง (ในอิมเมจทางการมีแค่ตัวจอง 1 MB)
  4. เปิดเครื่องอัตโนมัติ: หลังจากนั้นการเปิดแอปเหลือแค่ am start ครั้งเดียว บูตเย็นประมาณ 23 วินาที ถ้าโดนสแนปช็อตประมาณ 10 วินาที
การเปิดครั้งแรกช้าเป็นเรื่องปกติ เป็น "ต้นทุนครั้งเดียว" ครั้งต่อๆ ไปเปิดได้ทันที

3. การใช้งานประจำวัน

3.1 ติดตั้งแอป

เลือกได้สามวิธี:

  • ดับเบิลคลิกไฟล์ APK (ลงทะเบียนการเชื่อมโยงก่อน: การตั้งค่า → การรวมระบบและไฟล์ → การรวมเข้ากับระบบ → เชื่อมโยงไฟล์ .apk);
  • เลือก "ติดตั้ง APK" ในหน้าหลัก;
  • บรรทัดคำสั่ง: ApkStart.exe <เส้นทาง\to.apk>

รองรับแพ็กเกจแยกแบบ .apks / .xapk (ใช้ install-multiple อัตโนมัติ) ติดตั้งเสร็จจะสร้างทางลัดบนเดสก์ท็อปและเมนูเริ่มให้อัตโนมัติ

3.2 เปิดแอป

ดับเบิลคลิกไอคอนบนเดสก์ท็อป ทุกแอปใช้รันไทม์ตัวเดียวกัน ดังนั้น แอปที่สองเริ่มได้เกือบทันที

3.3 หน้าต่างและการแสดงผล

การทำงานวิธีทำ
สลับเต็มจอ / หน้าต่างF11 หรือเมนูถาดระบบ (คลิกขวา) โหมดเต็มจอแค่ขยายหน้าต่าง ไม่เปลี่ยนสัดส่วนภาพ
หมุนแนวนอน / แนวตั้งCtrl+Alt+R (ทั้งระบบ) หรือปุ่มหมุนที่แถบชื่อเรื่อง ทิศทางจะถูกจำไว้ให้แอปนั้น
เต็มจออัตโนมัติการตั้งค่า → การแสดงผลและหน้าต่าง → ใช้เต็มหน้าจออัตโนมัติ (ใช้ร่วมกับ "บังคับทิศทาง" ได้ผลดีที่สุด)
บังคับแนวนอน/แนวตั้งการตั้งค่า → การแสดงผลและหน้าต่าง → แนวหน้าจอ
รันไทม์จะรีสตาร์ทเฉพาะครั้งที่ "ทิศทางจอไม่ตรงกับทิศทางแอป" (ประมาณ 40 วินาที แถบชื่อเรื่องจะแจ้งไว้) แอปที่ทิศทางเดียวกันหลังจากนั้นเปิดได้ทันที

3.4 คีย์ลัด

ปุ่มหน้าที่
F11สลับโหมดเต็มจอ / หน้าต่าง

Ctrl+Rหมุนภายในหน้าต่างเปลือก (ในโหมดหน้าต่างดั้งเดิมให้ใช้ Ctrl+Alt+R)

3.5 แชร์ไฟล์ (Windows ↔ Android)

%USERPROFILE%\ApkStartShared บนเครื่องและ /sdcard/ApkStartShared ใน Android ซิงก์สองทางภายในไม่กี่วินาที ที่อยู่: การตั้งค่า → การรวมระบบและไฟล์ → การแชร์ไฟล์ (กด "ซิงก์เดี๋ยวนี้" หรือเปิดโฟลเดอร์ได้)

การวินิจฉัยและซ่อมแซมตรวจสอบเครื่อง ไดรเวอร์ / แพตช์ความเข้ากันได้ ตรวจสอบอัตโนมัติ
การรวมระบบและไฟล์เดสก์ท็อปและแอป การแชร์ไฟล์ การรวมเข้ากับระบบ
อัปเดตและเกี่ยวกับอัปเดตซอฟต์แวร์ เกี่ยวกับ
ห้องทดลองหลายหน้าต่าง/หลายแอปแบบ Windows ดั้งเดิม (ทดลอง) จำนวนแอปที่เก็บไว้เบื้องหลัง
ห้องทดลอง · โหมดหลายแอป (ทดลอง): เมื่อเปิด การเปิดแอปใหม่จะไม่บังคับปิดแอปก่อนหน้าอีก หลายแอปค้างอยู่เบื้องหลังและสลับกลับได้ทุกเมื่อโดยคงสถานะเข้าสู่ระบบ เนื่องจากรันไทม์ Android มีหน้าต่างอีมูเลเตอร์เดียว ณ เวลาหนึ่งจึงแสดงภาพแอปด้านหน้าได้เพียงแอปเดียว ไม่ใช่หลายหน้าต่างเคียงข้างกันจริงๆ และการเปิดจะใช้หน่วยความจำเพิ่มขึ้น ปิดเป็นค่าเริ่มต้น หากต้องการความเสถียรให้ข้ามไปได้เลย

3.7 อัปเดตออนไลน์

การตั้งค่า → อัปเดตและเกี่ยวกับ → ตรวจสอบอัปเดต หรือคลิกขวาที่ถาดระบบ → ตรวจสอบอัปเดต ตัวอัปเดตวัดและเลือกแหล่งที่เร็วที่สุดทุกครั้ง (GitHub / Gitee / มิเรอร์) ดาวน์โหลดแบบขนานเป็นชิ้นๆ และเปลี่ยนแหล่งอัตโนมัติเมื่อล้มเหลว การอัปเดตไม่ทำให้รันไทม์ แอปที่ติดตั้ง และสแนปช็อตหาย

รุ่นพกพาใหม่รองรับ การอัปเดตแบบเพิ่มส่วน: ทุกครั้งที่ปล่อยเวอร์ชันจะมี "รายการโค้ด" และแพ็กเกจเล็กที่มีเฉพาะโค้ดโปรแกรม (ไม่กี่ MB เทียบกับทั้งแพ็กเกจประมาณ 100 MB) หากเวอร์ชันเปลือก Electron ของคุณไม่เปลี่ยน การอัปเดตจะดาวน์โหลดแค่แพ็กเกจเล็กนี้ ตรวจสอบทีละไฟล์แล้วแทนที่โค้ดโปรแกรม ใช้เวลาไม่กี่วินาที หากเวอร์ชันเปลือกเปลี่ยน รายการโค้ดหายไป หรือการตรวจสอบใดไม่ผ่าน จะถอยกลับไปดาวน์โหลดแพ็กเกจเต็มอัตโนมัติ ไม่ทำให้โปรแกรมเสียจากการอัปเดต รุ่น Store ยังให้ Microsoft Store อัปเดตเช่นเดิม

หมายเหตุ: เฉพาะผู้ที่ติดตั้งรุ่นพกพาจาก GitHub / Gitee ผ่าน "ตรวจสอบอัปเดต" เท่านั้นที่ได้อัปเดตแบบเพิ่มส่วน ส่วนที่ติดตั้งจาก Microsoft Store ใช้ช่องทางของ Store การอัปเดตแบบเพิ่มส่วนไม่กระทบแอปที่ติดตั้ง ข้อมูล Android รันไทม์ และสแนปช็อต

4. ทำความเข้าใจแนวคิดหลักสามอย่าง (กุญแจสำคัญในการอ่านข้อความผิดพลาด)

"ปัญหาแปลกๆ" ส่วนใหญ่มีต้นเหตุอยู่ที่สามสิ่งด้านล่างนี้ ใช้เวลาหนึ่งนาทีทำความเข้าใจ แล้วการแก้ปัญหาจะง่ายขึ้นมาก

4.1 รันไทม์ / อิมเมจระบบ

ApkStart ไม่ได้จำลอง "Android เปล่าๆ" แต่โหลด อิมเมจระบบ Android 14 ที่สมบูรณ์ เป็นฐาน ตั้งแต่ 0.6.3 มี อิมเมจสากลเพียงอันเดียว (Google Play x86_64) ทั้งแอป x86 และ ARM รันบนอิมเมจนี้ ไม่แบ่งเป็น "อิมเมจ AOSP / อิมเมจความเข้ากันได้" สองชุดเหมือนรุ่นเก่าอีกแล้ว

  • อิมเมจหาย / เสียหาย / ไม่เข้ากับข้อมูลผู้ใช้เก่า → เปิดเครื่องไม่ติด ค้างตอนบูต รีสตาร์ทวนซ้ำ
  • ข้อมูลผู้ใช้ (/data) เป็นชั้นส่วนต่างบางๆ ส่วนอิมเมจระบบใช้ร่วมกันทั้งเครื่องเพียงชุดเดียว

4.2 การเร่งความเร็วด้วยฮาร์ดแวร์

อีมูเลเตอร์จะเร็วได้ต้องใช้การเร่งความเร็วด้วย CPU virtualization บน Windows มีแค่สองทาง:

วิธีคืออะไรใครต้องใช้สิทธิ์ผู้ดูแลระบบติดตั้งเสร็จต้องรีสตาร์ทไหม
WHPXฟีเจอร์ในตัวของ Windows "Windows Hypervisor Platform" (HypervisorPlatform)ตอนเปิดฟีเจอร์นี้ต้อง
AEHDไดรเวอร์เคอร์เนลของ Google เองตอนติดตั้งไดรเวอร์ไม่ต้อง

ไม่มีการเร่งความเร็วก็ยังรันได้ (จำลองด้วยซอฟต์แวร์ล้วน TCG) แค่เปิดเครื่องจะช้าไปหลายนาทีและภาพอาจกระตุก — นี่คือ "ช้า" ไม่ใช่ "เริ่มไม่สำเร็จ" ApkStart จะถอยกลับอัตโนมัติ และลองใหม่อัตโนมัติสูงสุด 4 ชุดพารามิเตอร์ ตามลำดับ "ตัวเรนเดอร์ → วิธีเร่งความเร็ว → หน่วยความจำ/บูตเย็น"

อย่าถือว่า VirtualMachinePlatform (ที่ WSL2 ใช้) เป็นสวิตช์เร่งความเร็ว สิ่งที่อีมูเลเตอร์ต้องการคือ HypervisorPlatform ถ้าเปิดแค่อย่างแรก emulator -accel-check ก็ยังบอกว่าใช้ไม่ได้

4.3 เลเยอร์แปล ARM

แอป Android ของจีนส่วนใหญ่มีเฉพาะ ไลบรารีเนทีฟ ARM (arm64-v8a / armeabi-v7a) แต่อิมเมจระบบเป็น x86_64 — จึงต้องมี "เลเยอร์แปล" ส่งคำสั่ง ARM ให้ CPU แบบ x86 อิมเมจสากลใน 0.6.3 มีเลเยอร์ ndk_translation เวอร์ชันใหม่มาในตัว จึงติดตั้งแอป ARM ได้โดยปกติโดยไม่ต้องตั้งค่าใดๆ

  • เมื่อเจอแอป ARM ครั้งแรก หากส่วนประกอบของเลเยอร์แปลยังไม่พร้อม ApkStart จะเติมอิมเมจความเข้ากันได้ให้อัตโนมัติและรีสตาร์ทรันไทม์เพื่อลองใหม่ (ดู 6.3)
  • อิมเมจเก่า (API 30) เข้ากันไม่ได้กับเลเยอร์แปลรุ่นใหม่ (เช่น แอปของ ByteDance ทำให้เกิด DoBadTrampoline SIGABRT) อิมเมจ Android 14 แก้ไขแล้ว

5. เมื่อเจอปัญหาให้ทำสิ่งนี้ก่อน: ตรวจสอบเครื่องและตรวจสอบอัตโนมัติ

ก่อนจะเปิดคู่มือนี้ ให้โปรแกรมตรวจตัวเองก่อน ปัญหาส่วนใหญ่มันแก้เองได้อัตโนมัติ

5.1 ตรวจสอบเครื่อง · ตั้งค่าอัตโนมัติ

ที่อยู่: การตั้งค่า → การวินิจฉัยและซ่อมแซม → เริ่มตรวจสอบเครื่อง

  • ตรวจอะไร: CPU virtualization (VT-x/SVM) เปิดหรือยัง Hyper-V / Windows Hypervisor Platform ใช้ได้หรือไม่ การ์ดจอ/VRAM/ไดรเวอร์ หน่วยความจำ เวอร์ชันระบบ emulator -accel-check และไดรเวอร์ AEHD
  • กด ใช้ค่าที่แนะนำ เพื่อเขียนตัวเลือกที่ปลอดภัยให้อัตโนมัติ: หน่วยความจำ / จำนวนคอร์ / ความละเอียดการเรนเดอร์ / คุณภาพภาพ / บังคับใช้การจำลองด้วยซอฟต์แวร์เมื่อไม่มีการเร่งความเร็ว และบันทึกเป็นไดรเวอร์ของเครื่องนี้ เพื่อใช้อัตโนมัติต่อไป
  • ผลลัพธ์แบ่งระดับ: ok (ปกติ) / warn (ใช้ได้แต่ควรปรับปรุง) / bad (ไม่แก้ก็รันไม่ได้) ทุกรายการมีสีและคำอธิบาย

มีสองอย่างที่คุณต้องทำเอง:

  • Virtualization ใน BIOS: รีสตาร์ทเข้า BIOS → เปิด Intel VT-x / AMD SVM → Enabled (ขั้นตอนนี้โปรแกรมทำแทนไม่ได้)
  • ฟีเจอร์ Windows / ไดรเวอร์เร่งความเร็ว: ดู 6.1

5.2 ตรวจสอบอัตโนมัติ (ดีบักอัตโนมัติ)

ที่อยู่: การตั้งค่า → การวินิจฉัยและซ่อมแซม → "ตรวจสอบอัตโนมัติ · วินิจฉัยอัจฉริยะ"

เบื้องหลังจะตรวจเครื่องทุก 10 นาที แล้วแสดงปัญหาแบ่งเป็นหมวด แต่ละรายการ แก้ได้ในคลิกเดียว (รีสตาร์ทรันไทม์ ล้างล็อก ล้างโปรเซสกำพร้า ทำสแนปช็อตเป็นโมฆะ ล้างดิสก์ รีเซ็ตเครือข่าย Android ฯลฯ) และตรวจซ้ำให้เองหลังแก้:

หมวดปัญหาที่ครอบคลุม
รันไทม์สาเหตุจริงที่การเริ่มครั้งก่อนล้มเหลว การบูตค้าง ไฟล์ล็อกตกค้าง โปรเซสอีมูเลเตอร์กำพร้า สแนปช็อตเปลือกว่าง ไม่มีการเร่งความเร็วด้วยฮาร์ดแวร์
การเชื่อมต่ออุปกรณ์adb ยังไม่ได้รับอนุญาต offline รันไทม์ทำงานอยู่แต่ adb มองไม่เห็นอุปกรณ์
พื้นที่จัดเก็บพื้นที่ดิสก์เหลือ ค่าพาร์ติชันข้อมูลไม่ตรงกับค่าจริง โฟลเดอร์แชร์เขียนไม่ได้
การตั้งค่านโยบายแนวหน้าจอขัดกับจอจริง เต็มจออัตโนมัติไม่มีผลในหน้าต่างแยก
เครือข่าย/บันทึกฝั่ง Android ไม่มีเน็ต แหล่งดาวน์โหลดเข้าไม่ได้ ข้อผิดพลาดในบันทึกล่าสุด
สองหลักการ: การตรวจจับที่ล้มเหลวจะไม่ถูกนับเป็นปัญหา (ถ้าอ่านสถานะไม่ได้จะรายงานว่า "ไม่ทราบ" ไม่รายงานมั่ว) และปัญหาเก่าเดิมจะไม่รบกวนซ้ำ

5.3 ส่งออกรายงานการวินิจฉัย

ที่อยู่: การตั้งค่า → การวินิจฉัยและซ่อมแซม → ส่งออกรายงานการวินิจฉัย (หรือปุ่มชื่อเดียวกันในหน้าการรวมระบบ)

รายงานเป็นข้อความธรรมดา มีการตั้งค่าของเครื่อง พารามิเตอร์เริ่มต้นที่เลือกอัตโนมัติ บันทึก และข้อสรุปการวินิจฉัย แนบไปเมื่อแจ้งปัญหาจะช่วยให้หาสาเหตุได้เร็วขึ้นมาก

5.4 คู่มือในตัวและบทช่วยสอนอัตโนมัติ

ตั้งแต่ 0.6.3 คู่มือนี้ถูก ฝังอยู่ในโปรแกรม ปุ่ม "?" ที่แถบชื่อเรื่องหน้าหลัก และปุ่ม "เปิดคู่มือการใช้งาน (รวมวิธีแก้ปัญหา)" ใน การตั้งค่า → เกี่ยวกับ เปิดคู่มือได้โดยตรง ค้นหา เลื่อนดู พิมพ์ หรือบันทึกเป็น PDF ได้ เมื่อเปิดจะข้ามไปยังหัวข้อที่เกี่ยวกับปัญหาปัจจุบันให้อัตโนมัติ

การตรวจสอบ/ซ่อมแซมอัตโนมัติยังนำบทช่วยสอนมาให้คุณถึงหน้าจอ:

  • เมื่อการตรวจสอบอัตโนมัติพบปัญหา ที่ด้านขวาของรายการจะมีปุ่ม "คู่มือ" กดแล้วไปยังหัวข้อที่เกี่ยวข้องโดยตรง;
  • ปัญหาเรื่องการเร่งความเร็วด้วยฮาร์ดแวร์ ติดตั้งไม่สำเร็จ เลเยอร์แปล ARM การอนุญาต adb ไม่มีเสียง และอื่นๆ เมื่อซ่อมแซมอัตโนมัติไม่สำเร็จ จะเด้งบทช่วยสอนที่เกี่ยวข้องขึ้นมาเอง ไม่ต้องมาเปิดหาที่นี่;
  • บทช่วยสอนเดียวกันจะเด้งอัตโนมัติเพียงครั้งเดียวต่อการรันหนึ่งรอบ ไม่ขัดจังหวะคุณซ้ำๆ
เปิดด้วยตนเอง: ปุ่ม ? ที่แถบชื่อเรื่อง ถ้าอยากปิดการเด้งอัตโนมัติชั่วคราว ให้ปิดการแจ้งเตือนในการตั้งค่าการตรวจสอบอัตโนมัติ บทช่วยสอนยังเปิดได้จากปุ่ม "คู่มือ" ที่รายการปัญหา

6. วิธีแก้ปัญหาที่พบบ่อย

6.1 ขึ้นข้อความ "ยังไม่ได้เปิดการเร่งความเร็วด้วยฮาร์ดแวร์" / เปิดเครื่องช้ามาก

อาการ: ในการตั้งค่า/การวินิจฉัยขึ้นว่า "ตอนนี้ไม่มีการเร่งความเร็วด้วยฮาร์ดแวร์" หรือ "การเร่งความเร็วด้วยฮาร์ดแวร์ใช้ไม่ได้" เปิดเครื่องช้าเป็นหลายนาที ภาพกระตุก

ทำความเข้าใจก่อน: โดยทั่วไปนี่คือ "ช้า" ไม่ใช่ "เปิดไม่ขึ้น" ApkStart ถอยไปใช้การจำลองด้วยซอฟต์แวร์ให้แล้ว จะเปิดการเร่งความเร็วก็ต่อเมื่ออยากให้ลื่นไหล

จัดการตามรุ่น:

  • รุ่นติดตั้ง / รุ่นพกพา: การตั้งค่า → การวินิจฉัยและซ่อมแซม → ตรวจสอบระบบ → หา "ยังไม่ได้เปิดการเร่งความเร็วด้วยฮาร์ดแวร์" → กด แก้ไข จะเด้ง UAC หนึ่งครั้งและเปิด WHPX ให้อัตโนมัติ ถ้าเปิดไม่ได้ (ระบบไม่รองรับหรือคุณกดไม่) จะเปลี่ยนไปติดตั้งไดรเวอร์ AEHD แทนอัตโนมัติ
  • รุ่น Microsoft Store (MSIX): แอปจาก Store ยกระดับสิทธิ์เองไม่ได้ การกด "แก้ไข" จะเปิดกล่อง "เปิดหรือปิดคุณลักษณะของ Windows" ให้ทำดังนี้:
  1. ติ๊ก "Windows Hypervisor Platform" (HypervisorPlatform);
  2. ยืนยัน แล้ว รีสตาร์ทคอมพิวเตอร์ หนึ่งครั้ง

หรือจะรันใน PowerShell แบบผู้ดูแลระบบ ก็ได้:

dism /online /enable-feature /featurename:HypervisorPlatform /all /norestart
dism /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
ข้อควรระวังสองข้อ: ① อย่าเปิดแค่ VirtualMachinePlatform เพราะนั่นไม่ใช่การเร่งความเร็วที่อีมูเลเตอร์ต้องการ ② ถ้า VT-x/SVM ใน BIOS ยังไม่เปิด ให้เปิดตาม 5.1 ก่อน ไม่เช่นนั้นเปิดฟีเจอร์ระบบไปก็ไม่มีผล ถ้าไดรเวอร์การ์ดจอเก่ากว่า 3 ปี ให้ไปอัปเดตจากเว็บไซต์ผู้ผลิต แต่ ApkStart จะไม่ติดตั้งไดรเวอร์ให้อัตโนมัติ (ลงผิดตัวแย่กว่าเดิม) การ์ดจอเก่าหรือการ์ดออนบอร์ดบางรุ่นต้องใช้แพตช์ความเข้ากันได้ ดูที่ การตั้งค่า → การวินิจฉัยและซ่อมแซม → ไดรเวอร์ · แพตช์ความเข้ากันได้

6.2 ติดตั้งไม่สำเร็จ (INSTALL_FAILED_*)

อาการ: ติดตั้งแอปแล้วขึ้นข้อผิดพลาด ข้อความมักขึ้นต้นว่า "ติดตั้งไม่สำเร็จ:" และลงท้ายด้วยรหัสข้อผิดพลาด INSTALL_*

ApkStart จะแปลข้อผิดพลาดภาษาอังกฤษต้นฉบับให้เข้าใจง่าย ตรวจสอบตามตารางด้านล่าง:

รหัสข้อผิดพลาดความหมายต้องทำอย่างไร
INSTALL_FAILED_NO_MATCHING_ABISแอปมีเฉพาะไลบรารี ARM แต่อิมเมจปัจจุบันไม่มีเลเยอร์แปล ARMโดยทั่วไปจัดการให้อัตโนมัติ: ApkStart สลับไปใช้อิมเมจความเข้ากันได้แล้วลองใหม่ ดูรายละเอียดที่ 6.3
INSTALL_FAILED_OLDER_SDKแอปต้องการ Android เวอร์ชันสูงกว่าอิมเมจเริ่มต้นคือ Android 14 (API 34) เลือก Android 16 (API 36) ที่ การตั้งค่า → ประสิทธิภาพและทรัพยากร → เวอร์ชัน Android ดาวน์โหลดอิมเมจประมาณ 1.9 GB แล้วรีสตาร์ทรันไทม์ ข้อมูลของสองเวอร์ชันแยกจากกัน
INSTALL_PARSE_FAILED_NO_CERTIFICATESAPK ไม่มีลายเซ็นที่ถูกต้องAPK เสียหายหรือไม่ใช่แพ็กเกจทางการ ให้หาไฟล์ติดตั้งมาใหม่
INSTALL_PARSE_FAILED_INCONSISTENT_CERTIFICATES / INSTALL_FAILED_UPDATE_INCOMPATIBLEลายเซ็นไม่ตรงกับเวอร์ชันที่ติดตั้งอยู่ถอนการติดตั้งเวอร์ชันเก่าก่อนแล้วค่อยติดตั้ง
INSTALL_FAILED_VERSION_DOWNGRADEอุปกรณ์มีเวอร์ชันที่สูงกว่าติดตั้งอยู่แล้วทับด้วยเวอร์ชันต่ำกว่าไม่ได้ ติดตั้งเวอร์ชันที่สูงกว่าหรือถอนการติดตั้งก่อน
INSTALL_FAILED_INSUFFICIENT_STORAGEพื้นที่ดิสก์ของรันไทม์ไม่พอล้างดิสก์ หรือย้ายโฟลเดอร์ข้อมูลรันไทม์ไปไดรฟ์ที่มีพื้นที่พอ (การตั้งค่า → การรวมระบบและไฟล์ → การรวมเข้ากับระบบ)
INSTALL_FAILED_INVALID_APKAPK เสียหาย/ไม่สมบูรณ์อาจดาวน์โหลดไม่เสร็จ ให้ดาวน์โหลดใหม่
INSTALL_FAILED_INVALID_URIเส้นทาง APK มีอักขระพิเศษ/ภาษาจีนย้าย APK ไปไว้ในเส้นทางที่เป็นภาษาอังกฤษล้วนแล้วค่อยติดตั้ง
INSTALL_FAILED_ALREADY_EXISTSมีแอปชื่อเดียวกันแต่ลายเซ็นต่างกันอยู่แล้วถอนการติดตั้งก่อน
INSTALL_FAILED_DEPRECATED_SDK_VERSIONแอปที่มุ่งเป้า Android เก่ามากจัดการให้อัตโนมัติ: ApkStart ลองใหม่ด้วยพารามิเตอร์ข้ามทางการ
INSTALL_FAILED_TEST_ONLYแพ็กเกจสำหรับทดสอบเท่านั้นจัดการให้อัตโนมัติ: เพิ่มพารามิเตอร์แพ็กเกจทดสอบแล้วลองใหม่
INSTALL_FAILED_MISSING_SHARED_LIBRARYฟีเจอร์ของอุปกรณ์/ไลบรารีของผู้ผลิตที่ต้องพึ่งไม่มีอยู่แอปพึ่งพาสภาพแวดล้อมของผู้ผลิตเฉพาะ ซึ่งอีมูเลเตอร์ให้ไม่ได้
INSTALL_FAILED_USER_RESTRICTIONระบบจำกัดการติดตั้งรีสตาร์ทรันไทม์แล้วลองใหม่
INSTALL_FAILED_CONFLICTING_PROVIDERชนกับ ContentProvider ของแอปที่มีอยู่ถอนการติดตั้งแอปที่ชนกัน
INSTALL_FAILED_INTERNAL_ERRORข้อผิดพลาดภายในระบบ (ส่วนใหญ่พื้นที่ไม่พอหรือยังบูตไม่เสร็จ)รีสตาร์ทรันไทม์ รอให้บูตเสร็จแล้วลองใหม่
หากข้อผิดพลาดเป็นข้อความภาษาอังกฤษดิบที่ไม่อยู่ในตาราง ให้ส่งออกรายงานการวินิจฉัยตาม 5.3 แล้วส่งความเห็นมา

6.3 อิมเมจระบบไม่มีเลเยอร์แปล ARM / แอป ARM ติดตั้งไม่ได้หรือแครช

อาการ: ติดตั้งแล้วขึ้น INSTALL_FAILED_NO_MATCHING_ABIS โดยข้อความบอกว่าแอปมีเฉพาะไลบรารีเนทีฟ ARM และอิมเมจระบบปัจจุบันไม่มีเลเยอร์แปล ARM หรือติดตั้งได้แต่เปิดปุ๊บแครชปั๊บ ในบันทึกมี DoBadTrampoline, libndk_translation, UnsatisfiedLinkError, ...so not found

หลักการ: 0.6.3 ใช้ อิมเมจ Android 14 สากลเพียงอันเดียว รองรับทั้ง x86 และ ARM และมีเลเยอร์แปลในตัวแล้ว เวอร์ชันเก่าต้องสลับอิมเมจเอง สวิตช์ "อิมเมจความเข้ากันได้สากล (จัดการอัตโนมัติ)" ตอนนี้ มีไว้เพื่อความเข้ากันได้กับการตั้งค่าเก่าเท่านั้น โดยปกติไม่ต้องแตะ

ApkStart จะทำอะไรให้อัตโนมัติ:

  1. ตอนติดตั้งถ้าขึ้น NO_MATCHING_ABIS จะสลับไปใช้อิมเมจความเข้ากันได้ → รีสตาร์ทรันไทม์ → ติดตั้งแอปที่เคยติดตั้งกลับจากสำรอง APK ในเครื่อง → ติดตั้งใหม่ (ในบันทึกจะเห็น "กำลังสลับไปอิมเมจความเข้ากันได้และรีสตาร์ทรันไทม์…")
  2. ถ้าแอปแครชตอนเปิดและบันทึกชี้ชัดไปที่เลเยอร์แปล ARM (เช่น DoBadTrampoline) จะสลับไปใช้อิมเมจความเข้ากันได้ Android 14 แล้วลองใหม่ให้อัตโนมัติ (ในบันทึกจะเห็น "ตรวจพบการแครชของเลเยอร์แปล ARM กำลังสลับอิมเมจความเข้ากันได้อัตโนมัติ…")

สิ่งที่คุณต้องทำ:

  • อดทนรอ: การสลับอิมเมจจะรีสตาร์ทรันไทม์ ครั้งละประมาณ 40 วินาทีถึง 1 นาที ระหว่างนั้นอาจเห็นหน้าต่างแจ้งเตือน
  • ยืนยันว่าอิมเมจพร้อมแล้ว: การตั้งค่า → ทั่วไปและการติดตั้ง → รันไทม์และสภาพแวดล้อม ดูสถานะของ "อิมเมจความเข้ากันได้สากล (จัดการอัตโนมัติ)" ถ้าขึ้นว่ายังไม่ได้ดาวน์โหลด ให้กด "ดาวน์โหลดอิมเมจความเข้ากันได้" (ประมาณ 1.5 GB) เมื่อเสร็จแล้ว รีสตาร์ทรันไทม์ จึงจะมีผล
  • ยังแครชอยู่: แอปบางตัวมีการตรวจจับอีมูเลเตอร์ที่ลึกกว่า (บังคับตรวจเซนเซอร์จริง เบสแบนด์ ฯลฯ) ไม่สามารถรันในอีมูเลเตอร์ได้ แอปแบบนี้จะแสดงคำอธิบาย ถือเป็นข้อจำกัด ไม่ใช่ความผิดปกติ

ถ้าเห็น "ติดตั้งไม่สำเร็จ" สีแดง แต่ข้อความกลับบอกว่า "กำลังสลับอิมเมจความเข้ากันได้อัตโนมัติแล้วลองใหม่" ต้องทำอย่างไร?

นี่คือข้อผิดพลาดการแสดงผลของเวอร์ชันเก่า: ไฟล์อิมเมจอยู่บนดิสก์ แต่ถูกนำไปใช้กับรันไทม์เก่าที่ไม่ได้เปิดเลเยอร์แปล การสลับแล้วลองใหม่ถูกข้ามไป รายงานว่าล้มเหลวทันที แต่ข้อความยังบอกว่า "กำลังลองใหม่" คุณไม่ได้ใช้โค้ดล่าสุด โปรดอัปเกรดเป็นบิลด์ล่าสุดของ 0.6.4 (เวอร์ชันที่คู่มือนี้อ้างถึงแก้แล้ว: ก่อนติดตั้งจะตรวจความสามารถแปลจริงของรันไทม์ปัจจุบัน ไม่ใช่ดูแค่ว่าไฟล์อิมเมจอยู่หรือไม่; NO_MATCHING_ABIS จะทริกเกอร์สลับ + รีสตาร์ท + ล้างสแนปช็อตเก่า + ติดตั้งใหม่เสมอ; ถ้าครั้งที่สองยังล้มเหลวจะแจ้งตามจริง ไม่อ้างว่า "กำลังลองใหม่" อีก) หลังอัปเกรดให้ติดตั้งอีกครั้ง

ทดสอบจริง: แอปซีรีส์สั้นฟรี (com.phoenix.read, arm64-v8a-only) บนอิมเมจ Android 14 + เลเยอร์แปลรุ่นใหม่ ติดตั้งได้ เข้าฟีดแนะนำ และเล่นวิดีโอได้ปกติ รันไทม์ปัจจุบัน ro.product.cpu.abilist = x86_64,arm64-v8a เลเยอร์แปลทำงานแล้ว

6.4 adb ยังไม่ได้รับอนุญาต (อนุญาตการดีบักผ่าน USB)

อาการ: การวินิจฉัยรายงาน "adb ยังไม่ได้รับอนุญาต" หรือ "การอนุญาตดีบัก Android ยังไม่เสร็จ" adb devices แสดง unauthorized และแอปเปิดไม่ขึ้นเลย

วิธีที่ถูกต้อง (ตามลำดับ):

  1. ดูว่ามีหน้าต่างอีมูเลเตอร์ที่แสดงกล่อง "อนุญาตการดีบักผ่าน USB หรือไม่?" ค้างอยู่หรือไม่ — ไปที่หน้าต่างนั้นแล้วกด อนุญาต และติ๊ก "อนุญาตเสมอจากคอมพิวเตอร์เครื่องนี้" ครั้งต่อไปจะไม่ถามอีก
  2. ถ้าหน้าต่างกดไม่ได้หรือไม่ขึ้นมาเลย: การตั้งค่า → ทั่วไปและการติดตั้ง → รีเซ็ตข้อมูล Android แล้วลองใหม่ (จะล้างแอปที่ติดตั้งไว้ ไฟล์ APK ยังอยู่และจะติดตั้งใหม่ให้อัตโนมัติ ตัวระบบไม่ได้รับผลกระทบ)
⚠️ ห้ามลบ %USERPROFILE%\.android\adbkey เด็ดขาด ทดสอบจริงแล้วพบว่าเป็นการกระทำที่ตรงกันข้าม: Android จะเขียนกุญแจสาธารณะใหม่เฉพาะเมื่อไม่มีไฟล์ adb_keys เท่านั้น ถ้าคุณเปลี่ยนกุญแจส่วนตัวใหม่ กุญแจสาธารณะเก่าที่เก็บในระบบก็ยังมีผล ทั้งสองไม่ตรงกัน จะอนุญาตไม่สำเร็จตลอดไป

ตรวจสอบด้วยบรรทัดคำสั่ง: เซิร์ฟเวอร์ adb ของ ApkStart ทำงานที่ พอร์ตเฉพาะ 5044 (แยกจาก 5037 ของคุณโดยสิ้นเชิง):

$env:ANDROID_ADB_SERVER_PORT = 5044
adb devices    # ควรเห็น emulator-5554
อย่า adb connect ด้วยมือไปที่พอร์ต 5555 — อิมเมจ Play จะเด้ง "อนุญาตการดีบักผ่าน USB" ทับบนแอป ดูเหมือนโปรแกรมพัง

6.5 ดับเบิลคลิกไอคอนแล้วไม่ตอบสนอง / หมุนค้าง / มีหน้าต่างที่มีปุ่มหมุนโผล่ขึ้นมา

ปัญหากลุ่มนี้เกือบทั้งหมดชี้ไปที่ จุดเข้าสำหรับเปิดหรือการเข้ารับช่วงหน้าต่าง ตรวจตามลำดับด้านล่าง

① ยืนยันว่าคุณใช้โปรแกรมเวอร์ชันใหม่

  • ดูต้นบันทึก %APPDATA%\ApkStart\logs\app.log: ควรเป็น start v0.6.4 ถ้าขึ้น v0.5.x แสดงว่าไอคอนบนเดสก์ท็อป/เมนูเริ่มชี้ไปโฟลเดอร์เวอร์ชันเก่า
  • เวอร์ชันเก่า (0.5.x) ไม่มีรันไทม์ในตัวและใช้หน้าต่างแบบฝังเป็นค่าเริ่มต้น → "ช้ามาก + หน้าต่างเปลือกที่มีปุ่มหมุน" เปลี่ยนเป็น 0.6.4 และชี้ทางลัดไปที่ ApkStart.exe ตัวใหม่

② ตั้งความคาดหวังเรื่องเวลาเปิดเครื่อง

บูตเย็นประมาณ 23–48 วินาที และรีสตาร์ทเมื่อเปลี่ยนทิศทางประมาณ 50 วินาที ถือเป็นช่วงปกติ ระหว่างนี้คลิกไอคอนแล้วดูเหมือน "ไม่ตอบสนอง" แต่จริงๆ กำลังบูตอยู่เบื้องหลัง อย่าคลิกซ้ำหลายครั้ง: การคลิกซ้ำทำให้อินสแตนซ์ที่สองเข้ามารับช่วงอีมูเลเตอร์ และเมื่ออินสแตนซ์แรกออกการจัดการท้ายอาจปิดอีมูเลเตอร์ไปด้วย ทำให้ล้มเหลว (0.6.3 เพิ่มการป้องกันด้วย owner.pid แล้ว แต่การรอคิวก็ยังดูเหมือนไม่ตอบสนอง) คลิกครั้งเดียวแล้วรอให้ขึ้น

③ การเข้ารับช่วงหน้าต่างดั้งเดิมไม่สำเร็จ → ถอยไปเป็นหน้าต่างแบบฝังที่มีปุ่มหมุน

ถ้าในบันทึกมี attach failed หรือ emu:0 แสดงว่าตัวแทนหน้าต่างหาหน้าต่างอีมูเลเตอร์ไม่เจอ โปรแกรมจึงถอยไปโหมดฝัง (คือหน้าต่างเปลือกที่มีแถบชื่อเรื่องและปุ่มหมุนที่คุณเห็น)

  • เกิดง่ายเมื่อเริ่มจาก directory junction หรือเส้นทางที่ไม่เป็นมาตรฐาน 0.6.3 ทำให้ตัวแทนแปลงเป็นเส้นทางจริงก่อนจับคู่ หากยังเกิดอยู่ ให้แนบบันทึกส่งความเห็นมา

④ รีเซ็ตข้อมูล Android (ทางเลือกสุดท้าย)

การตั้งค่า → ทั่วไปและการติดตั้ง → รีเซ็ตข้อมูล Android (มีการยืนยันสองชั้น) จะล้างแอปที่ติดตั้งและข้อมูล แต่เก็บตัวระบบไว้ รายชื่อแอปจะยังอยู่และติดตั้งใหม่อัตโนมัติเมื่อเปิด ใช้กับกรณีที่พาร์ติชันข้อมูลเสียหาย หรือ /data เมานต์ไม่ได้จนเปิดไม่ติดในรูปแบบต่างๆ

6.6 ตารางอ้างอิงด่วนสำหรับปัญหาการเริ่มต้นอื่นๆ

ข้อผิดพลาดของรันไทม์เหล่านี้ ApkStart ส่วนใหญ่ จัดการให้อัตโนมัติแล้ว ตารางบอกว่ามันทำอะไรไปและคุณทำอะไรเพิ่มได้ หากการจัดการอัตโนมัติไม่ได้ผล ให้ส่งออกรายงานการวินิจฉัยตาม 5.3

หัวข้อการวินิจฉัยการจัดการอัตโนมัติสิ่งที่คุณทำเพิ่มได้
การเร่งความเร็วด้วยฮาร์ดแวร์ใช้ไม่ได้ถอยไปใช้การจำลองด้วยซอฟต์แวร์เปิดการเร่งความเร็วตาม 6.1
จัดสรรหน่วยความจำไม่สำเร็จลดหน่วยความจำและจำนวนคอร์ปิดโปรแกรมที่กินหน่วยความจำ
พอร์ตอีมูเลเตอร์ถูกใช้อยู่เปลี่ยนไปพอร์ตว่างอัตโนมัติออกจากอีมูเลเตอร์อื่น (Nox/MuMu/BlueStacks) หรือรีสตาร์ท
ไฟล์ล็อกตกค้าง / "Running multiple emulators with the same AVD"ล้างล็อก AVD แล้วลองใหม่ตรวจว่าไม่มีอีมูเลเตอร์อื่นใช้รันไทม์เดียวกันอยู่
อิมเมจระบบหาย/เสียหาย/ไม่เข้ากับข้อมูลเก่าบูตใหม่ด้วยข้อมูลผู้ใช้ที่สะอาดการตั้งค่า → รันไทม์: ลบอิมเมจแล้วดาวน์โหลดใหม่
สแนปช็อตเริ่มเร็วเสียหายทิ้งสแนปช็อตเก่าแล้วบูตเย็นจะสร้างใหม่เมื่อออกจากโปรแกรมตามปกติครั้งหน้า หรือปิดสแนปช็อต
ส่วนประกอบรันไทม์ถูกลบ / ขาดรันไทม์ VC++—เพิ่ม ApkStart ในรายการยกเว้นของแอนตี้ไวรัสแล้วแตกไฟล์ใหม่ ติดตั้งรันไทม์ Microsoft VC++ 2015-2022
พื้นที่ดิสก์ไม่พอ—ย้ายโฟลเดอร์รันไทม์ไปไดรฟ์ที่มีพื้นที่พอ ปิดสแนปช็อต/ลดพาร์ติชันข้อมูล
เส้นทางมีภาษาจีน/อักขระพิเศษใช้เส้นทางสั้นแทนอัตโนมัติย้าย ApkStart ไปโฟลเดอร์ที่เป็นภาษาอังกฤษล้วน (เช่น C:\ApkStart)
CPU ขาดชุดคำสั่ง (AVX/SSE4)—ส่วนมากเป็นแค่คำเตือนและยังบูตได้ ถ้าไม่ได้ให้ใช้เครื่องที่รองรับ VT-x/AVX หรือเอนจินรุ่นเก่า
รันไทม์ปัจจุบันไม่รับโหมด GPU นั้นเลือกโหมด GPU ที่ใช้ได้ใหม่ตามเวอร์ชันเอนจิน—
การ์ดจอ/ข้อผิดพลาดที่ไม่ทราบสาเหตุลองใหม่อัตโนมัติด้วยหลายชุดพารามิเตอร์อัปเดตไดรเวอร์การ์ดจอ หรือเขียนแพตช์ความเข้ากันได้ ถ้ายังไม่ได้ให้ส่งออกรายงานการวินิจฉัย

ไอคอนบนเดสก์ท็อปแสดงเป็นไอคอนของ ApkStart / ไอคอนว่าง: การตั้งค่า → การรวมระบบและไฟล์ → การรวมเข้ากับระบบ → สร้างทางลัดใหม่ (เขียนทางลัดบนเดสก์ท็อปและเมนูเริ่มใหม่ตามรายชื่อแอปปัจจุบัน แก้ไอคอนและตัวตนบนแถบงานไปพร้อมกัน) หากทางลัดถูกย้ายที่จนเส้นทางใช้ไม่ได้ ก็ต้องสร้างใหม่เช่นกัน

6.7 แอปไม่มีเสียง / เสียงเบามาก

อาการ: วิดีโอและเสียงแจ้งเตือนในแอป Android เงียบสนิท หรือโปรแกรม Windows อื่นมีเสียงแต่มีเฉพาะแอปใน ApkStart ที่ไม่มีเสียง

แยกให้ออกก่อน: ถ้าระบบเองก็ไม่มีเสียง ให้แก้เสียงของ Windows ก่อน ต้องเป็นกรณีที่ไม่มีเสียงเฉพาะแอปใน ApkStart จึงทำตามด้านล่าง

  1. ระดับเสียงและอุปกรณ์เอาต์พุตของ Windows: คลิกไอคอนเสียงบนแถบงาน ตรวจว่าไม่ได้ปิดเสียงและระดับเสียงไม่ใช่ 0 และอุปกรณ์เอาต์พุตเป็นหูฟัง/ลำโพงที่คุณใช้อยู่ เปิด "ตัวผสมระดับเสียง" ดูว่าแถว ApkStart / รันไทม์ Android ถูกปิดเสียงแยกหรือถูกดึงเป็น 0 หรือไม่
  2. ระดับเสียงในแอป: บางแอปตั้งระดับเสียงสื่อเป็น 0 ตอนเข้าครั้งแรก ให้เพิ่มในการตั้งค่าของแอปเองหรือด้วยปุ่มเสียงของ Android แอปอย่าง Bilibili / TikTok อาจปิดเสียงเล่นอัตโนมัติในแอปไว้ด้วย
  3. สวิตช์เสียงของ ApkStart: การตั้งค่า → ประสิทธิภาพและทรัพยากร → เสียง Android ต้องติ๊กไว้ การตรวจสอบอัตโนมัติจะตรวจตัวเลือกนี้ หากพบว่าถูกปิดจะรายงานที่ การตั้งค่า → การวินิจฉัยและซ่อมแซม กด "แก้ไข" ครั้งเดียวก็เปิดกลับให้ หลังแก้ต้องรีสตาร์ทรันไทม์ Android หนึ่งครั้ง (รันไทม์จะเริ่มด้วย -no-audio เฉพาะเมื่อปิดทั้งเสียงและไมโครโฟน การแก้ขณะรันอยู่จะไม่ทำให้มีเสียงทันที)
  4. บริการเสียงของ Windows: กด Win+R พิมพ์ services.msc หา Windows Audio ตรวจว่าสถานะเป็น "กำลังทำงาน" และประเภทการเริ่มเป็น "อัตโนมัติ" ถ้าถูกปิดใช้งาน ให้คลิกขวาแล้วเริ่ม การตรวจสอบอัตโนมัติของ 0.6.3 ก็ตรวจพบและแจ้งเตือนเรื่องนี้ด้วย ใน PowerShell แบบผู้ดูแลระบบรัน net start Audiosrv ได้
  5. หูฟังบลูทูธ / อุปกรณ์เอาต์พุตหลายตัว: หลังสลับไปหูฟังบลูทูธ บางครั้ง Windows ไม่ย้ายโปรแกรมที่ทำงานอยู่ไปให้ ให้ตัดแล้วเชื่อมหูฟังใหม่ หรือรีสตาร์ทรันไทม์ Android หนึ่งครั้ง
  6. ยังไม่มีเสียง: ส่งออกรายงานที่ การตั้งค่า → การวินิจฉัยและซ่อมแซม → ส่งออกรายงานการวินิจฉัย แล้วส่งความเห็นมา รายงานจะมีสถานะสวิตช์เสียงและบริการเสียง ซึ่งบอกได้โดยตรงว่าต้นเหตุคือการตั้งค่า บริการของระบบ หรือตัวแอปเอง
เมื่อซ่อมแซมอัตโนมัติไม่สำเร็จ โปรแกรมจะเปิดหัวข้อนี้ให้เอง ถ้าคุณปิดการแจ้งเตือนของการตรวจสอบอัตโนมัติ ก็เข้ามาเองได้จากปุ่ม "คู่มือ" ที่รายการตรวจสอบอัตโนมัติ หรือปุ่ม ? ที่แถบชื่อเรื่อง

6.8 รุ่น Store เริ่มไม่ขึ้น / 0xC0000135 (โหลด DLL ไม่สำเร็จ)

อาการ: เปิดแอปแล้วหมุนค้างหรือออกทันที ในรายงานการวินิจฉัยมีรหัสออก 0xC0000135 (ฐานสิบ 3221225781) พบมากในเวอร์ชันที่ ติดตั้งจาก Microsoft Store

แก้ความเข้าใจผิดที่พบบ่อยก่อน: 0xC0000135 แปลว่าแค่ "DLL บางตัวโหลดไม่สำเร็จ" ไม่ได้ แปลว่าต้องขาดรันไทม์ VC++ เสมอไป และไม่ได้แปลว่าแอนตี้ไวรัสลบไฟล์เสมอไป รหัสออกเดียวกันมีสามความเป็นไปได้ อย่าติดตั้งซ้ำวนไปมาตามข้อแรกอย่างเดียว:

  1. ข้อจำกัดเรื่องเส้นทางของรุ่น Store (MSIX): รุ่น Store ติดตั้งอยู่ในโฟลเดอร์แบบอ่านอย่างเดียว C:\Program Files\WindowsApps\... เมื่อรันไทม์ Android เรียกโปรเซสลูกอย่าง qemu จากโฟลเดอร์นี้ โปรเซสลูกจะหา DLL ด้วยเส้นทางสัมพัทธ์ ซึ่งอาจถูกการเปลี่ยนเส้นทางของคอนเทนเนอร์ / การแยกสภาพแวดล้อมขัดจังหวะ หาตัวที่พึ่งพาไม่เจอก็ออกด้วย 0xC0000135 นี่เป็นปัญหาเฉพาะของรุ่น Store และแก้ด้วยการติดตั้ง VC++ ซ้ำไม่ได้
  2. ขาดรันไทม์ VC++ จริงๆ: รันไทม์ Android (Qt6 / qemu) พึ่งพา Microsoft VC++ 2015-2022 (x64) ถ้า การตั้งค่า → การวินิจฉัยและซ่อมแซม รายงานชัดเจนว่า "ขาดรันไทม์ VC++ (x64)" นั่นคือ วัดจริงแล้วว่าไม่มีไฟล์ dll กด "แก้ไข" เพื่อติดตั้งในคลิกเดียวได้
  3. แอนตี้ไวรัสกักกันไฟล์รันไทม์: dll ในโฟลเดอร์รันไทม์ถูกกักกัน / ลบ ก็รายงานรหัสนี้เช่นกัน เพิ่มโฟลเดอร์ติดตั้งของ ApkStart และโฟลเดอร์ข้อมูลรันไทม์ในรายการยกเว้นของแอนตี้ไวรัส แล้วติดตั้งใหม่อีกครั้ง

ตรวจตามลำดับ:

ขั้นที่ 1 — ดูว่าขาด VC++ จริงหรือไม่: ถ้าในการตั้งค่ารายงานว่า "ขาดรันไทม์ VC++ (x64)" ให้กดแก้ไขในคลิกเดียว ติดตั้งเสร็จรีสตาร์ทคอมพิวเตอร์แล้วลองใหม่ อย่า ติดตั้งซ้ำเพียงเพราะรหัสออกคือ 0xC0000135 — ยืนยันก่อนว่ารายการนี้ถูกรายงานจริง

ขั้นที่ 2 — ไม่ได้รายงานเรื่อง VC++ แต่ยังล้มเหลว → ส่วนใหญ่เป็นปัญหาเส้นทางของรุ่น Store: นี่คือสาเหตุที่เป็นไปได้มากที่สุดตอนนี้ ลองตามลำดับ:

  • ออกจาก ApkStart ให้หมด (ไอคอนในถาดระบบ → ออก) แล้วเปิดใหม่;
  • ตรวจ "การเข้าถึงโฟลเดอร์ที่ควบคุม / การป้องกันแรนซัมแวร์" ของแอนตี้ไวรัส เพิ่ม ApkStart ในรายการยกเว้นแล้วรีสตาร์ท;
  • ถ้ายังไม่ได้ ให้ใช้ รุ่นพกพา (ApkStart-win64-portable ใน Releases ของ GitHub / Gitee) วางไว้ในโฟลเดอร์ภาษาอังกฤษล้วน (เช่น C:\ApkStart) แล้วรัน — รุ่นพกพาไม่ได้ติดตั้งใต้ WindowsApps จึงเลี่ยงข้อจำกัดนี้ได้โดยตรง

ขั้นที่ 3 — อยากได้ชื่อ DLL ที่ล้มเหลวแน่ชัด (ขั้นสูง): เมื่อแจ้งปัญหา สิ่งที่มีค่าที่สุดคือบอกผู้พัฒนาว่า dll ตัวไหนขาด ใน Event Viewer → Windows Logs → Application หา Application Error ของ ApkStart / emulator แล้วดูฟิลด์ FaultingModuleName หรือส่งออกรายงานที่ การตั้งค่า → การวินิจฉัยและซ่อมแซม → ส่งออกรายงานการวินิจฉัย แล้วแนบมาด้วย

ขั้นที่ 4 — ถ้า adb ก็แครชด้วย: ถ้าในบันทึกเหตุการณ์มี adb.exe รายงาน 0xC0000409 นั่นเป็นปัญหาแยกต่างหาก (การเชื่อมต่ออุปกรณ์ผิดปกติ) ไม่ใช่สาเหตุโดยตรงที่ทำให้ emulator ออก ให้จัดการการเริ่มต้นตามขั้นที่ 1–3 ก่อน และแจ้งปัญหา adb แยกต่างหากในความเห็น

หัวข้อนี้จะเด้งขึ้นเอง: เมื่อการเริ่มล้มเหลว / ซ่อมแซมไม่สำเร็จและถูกตัดสินว่าเป็นปัญหาประเภท DLL โปรแกรมจะเปิดมาที่นี่โดยตรง เข้าเองได้ทุกเมื่อจากปุ่ม "คู่มือ" ที่รายการตรวจสอบอัตโนมัติ หรือปุ่ม ? ที่แถบชื่อเรื่อง

6.9 แอปใช้ไมโครโฟนไม่ได้ / โทรด้วยเสียงและบันทึกเสียงไม่ได้

อาการ: ข้อความเสียง การโทร การบันทึกเสียง หรือการสแกนด้วยเสียงในแอปใช้ไม่ได้ ขึ้นข้อความอย่าง "ไม่มีไมโครโฟน / อุปกรณ์บันทึกเสียงใช้ไม่ได้"

  1. สวิตช์ไมโครโฟนของ ApkStart: การตั้งค่า → ประสิทธิภาพและทรัพยากร → การป้อนเสียงจากไมโครโฟน (แนะนำ) ต้องติ๊กไว้ เปิดเป็นค่าเริ่มต้น หากถูกปิด การตรวจสอบอัตโนมัติจะรายงานที่ การตั้งค่า → การวินิจฉัยและซ่อมแซม ว่า "ปิดการป้อนเสียงจากไมโครโฟนในการตั้งค่า" กด "แก้ไข" เพื่อเปิดและรีสตาร์ทรันไทม์ในคลิกเดียว หลังแก้ต้องรีสตาร์ทรันไทม์ Android หนึ่งครั้ง (สวิตช์นี้กำหนดว่าอีมูเลเตอร์จะเปิดอุปกรณ์บันทึกเสียงให้ Android เห็นหรือไม่)
  2. สิทธิ์ไมโครโฟนของ Windows: การตั้งค่า → ความเป็นส่วนตัวและความปลอดภัย → ไมโครโฟน ตรวจว่า "อนุญาตให้แอปเข้าถึงไมโครโฟนของคุณ" และ "อนุญาตให้แอปบนเดสก์ท็อปเข้าถึงไมโครโฟนของคุณ" เปิดทั้งคู่ — Android รันอยู่ในแอปเดสก์ท็อป ถ้าข้อนี้ไม่เปิด ระบบจะไม่ให้ไมโครโฟนเลย
  3. ยืนยันว่า Windows บันทึกเสียงได้: ใช้ "เครื่องบันทึกเสียง" ที่มากับระบบบันทึกสักช่วง ตรวจว่าไมโครโฟนและอุปกรณ์อินพุต (ไมค์หูฟัง / ไมค์เว็บแคม / ไมค์แยก) ทำงานปกติและไม่ได้ปิดเสียง
  4. เลือกอุปกรณ์อินพุตให้ถูก: ถ้าเสียบไมโครโฟนหลายตัว ให้ตั้งตัวที่ต้องการเป็นอุปกรณ์เริ่มต้นใน "การตั้งค่าเสียง → อินพุต" ของ Windows อีมูเลเตอร์จะใช้อุปกรณ์อินพุตเริ่มต้นของระบบ
  5. ความสัมพันธ์ระหว่างเสียงกับไมโครโฟน: อีมูเลเตอร์จะปิดระบบเสียงทั้งหมดเพื่อประหยัด CPU ก็ต่อเมื่อ "เสียง Android" และ "การป้อนเสียงจากไมโครโฟน" ปิดทั้งสองอย่าง เท่านั้น ถ้าเปิดไว้อย่างใดอย่างหนึ่ง อีกอย่างก็ใช้งานได้ตามปกติ
เมื่อไมโครโฟนถูกปิด ฝั่งแอปจะแค่ "หาอุปกรณ์บันทึกเสียงไม่เจอ" ไม่มีข้อผิดพลาดที่ชัดเจน การตรวจสอบอัตโนมัติมีหน้าที่รายงานเรื่องนี้ให้คุณเชิงรุก เข้าหัวข้อนี้เองได้จากปุ่ม ? ที่แถบชื่อเรื่อง

6.10 การเรนเดอร์ด้วยการ์ดจอแยก / ออนบอร์ด (การ์ดจอที่ใช้)

อาการ: คอมพิวเตอร์มีการ์ดจอแยกชัดเจน แต่ภาพของแอปกระตุกหรือเฟรมตก หรือโน้ตบุ๊กร้อนและกินไฟมากจนอยากใช้การ์ดออนบอร์ดเพื่อประหยัดไฟ

ภาพ Android ของ ApkStart ใช้ -gpu host เรนเดอร์ด้วยฮาร์ดแวร์ ซึ่งเรียกใช้การ์ดจอของเครื่องจริงๆ ตั้งแต่ 0.6.4 การ์ดจอทุกยี่ห้อ (NVIDIA / AMD / Intel) จะเลือกใช้ host ก่อนเป็นค่าเริ่มต้น ไม่ลด AMD/Intel ไปใช้การเรนเดอร์ด้วยซอฟต์แวร์เหมือนรุ่นเก่า ซึ่งเท่ากับจงใจทิ้งการ์ดจอ ถ้า host แครชบนเครื่องนี้ จะลดไปใช้แบ็กเอนด์ซอฟต์แวร์อัตโนมัติและไม่กระทบการใช้งาน

ระบุว่าจะใช้การ์ดใด: เมื่อเครื่องมีทั้งการ์ดแยกและออนบอร์ด บางครั้ง Windows จะจัดอีมูเลเตอร์ไปใช้การ์ดออนบอร์ด การตั้งค่า → ประสิทธิภาพและทรัพยากร → การ์ดจอที่ใช้ (แยก / ออนบอร์ด) ใช้ระบุให้ชัดเจนได้:

ตัวเลือกเหมาะกับ
ค่าเริ่มต้นของระบบ (แนะนำ)ให้ Windows เลือกเองตามพลังงาน/ภาระ สบายใจที่สุดสำหรับเครื่องส่วนใหญ่
ใช้การ์ดจอแยกก่อนเกม วิดีโอ งานที่ต้องการเฟรมเรตสูง กินไฟและร้อนมากกว่า
ใช้การ์ดจอออนบอร์ดก่อนแอปเบา ทำงานเบื้องหลัง โน้ตบุ๊กประหยัดไฟ ประสิทธิภาพอ่อนกว่า
  • ตัวเลือกนี้ทำงานผ่าน "ค่ากำหนดประสิทธิภาพกราฟิก" (UserGpuPreferences) ของ Windows สำหรับโปรเซสอีมูเลเตอร์ ใช้ได้เฉพาะ Windows 10 1803 ขึ้นไป ระบบเก่าจะข้ามไปเองและไม่กระทบการเริ่ม
  • มีผลเมื่อ เริ่มรันไทม์ Android ครั้งถัดไป หน้าตั้งค่าจะแสดงว่าตอนนี้มีผลแล้วหรือยัง
  • บนไดรเวอร์ AMD รุ่นเก่า host แครชเป็นครั้งคราว: อัปเดตไดรเวอร์การ์ดจอ ถ้ายังไม่ได้ ให้เปิดแพตช์ตัวอย่าง swangle สำหรับการ์ดออนบอร์ด AMD ที่มาในตัวที่ การตั้งค่า → การวินิจฉัยและซ่อมแซม → ไดรเวอร์ · แพตช์ความเข้ากันได้ เพื่อตรึงการเรนเดอร์ไปที่แบ็กเอนด์ที่เสถียรกว่า
